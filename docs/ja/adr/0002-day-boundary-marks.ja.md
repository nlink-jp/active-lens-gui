# ADR 0002 — 日境界の切断をどう見せるか

**ステータス:** 承認
**日付:** 2026-09-17
**対象:** `Models`、`Formatting`、`PopoverView`、`AnalysisView`
**対になる ADR:** `active-lens` ADR 0002（日境界の設定可能化）— 両者は同時に
リリースする。これが無ければエンジン側の新しい規則は目に見えず、フラグを出す
同梱 CLI が無ければこのアプリは何も表示できない。

---

## 1. 背景

`active-lens` ADR 0002 が `work.day_boundary` を追加した。`"strict"`——勤務日が
利用者以外によって定義されている職場向けの設定——では、境界を貫くセッションは
そこで切られ、各断片がそれぞれの日へ帰属する。

この規則は、現状のままでは正直に描けないものを 2 つ生む。

**ちょうど 05:00 に始まる勤務日。** 境界を越えた時点で既に作業が進行中だった日の
`work_start` は境界そのものになる。そういう日が並ぶと、ありえないほど几帳面な
勤務者に見える。そして旧来のペイロードには、本当に 05:00 に机に向かった人との
区別が無い。

**作業中にリセットされるメニューバーの見出し。** 見出しは now セッション
（ADR 0001 §2.7）である。`strict` では境界が新しいセッションを開くので、05:00、
キーボードに手を置いたまま数字が `0s` へ戻る。これは意図した挙動だが——一瞥する
価値があるのは今日に計上されるほうの数字だ——最もよく見られる面での説明の無い
リセットは、データを失ったように読める。

## 2. 決定

**フラグは復号する。再導出しない。** `carried_in` / `carried_out` が各日・各
セッション・now セッションに、`day_boundary` と `day_start_hour` が timeline
ペイロードと `status` に届く。日がどこで始まるかについてアプリは意見を持たない
——ADR 0001 でエンジンの持ち物になったものは、今回もエンジンに留まる。

**新しいフィールドはすべて optional。** 0.3.0 より古い同梱 CLI はどれも出さず、
それでもアプリは動かなければならない。欠落は「carried ではない」、`day_boundary`
の欠落は既定の規則、と読む。沈黙は旧挙動として読み、推測しない。

**切断は、それが現れる場所で示す。**

- 勤務ログ: carried-in の行には `arrow.turn.down.right` を前置し、carried-out の
  行には `arrow.right.to.line` を後置し、行そのものに説明のツールチップを付ける。
  両端が実在する行にはツールチップを付けない（空のツールチップも付けない）。
- 勤務ログのヘッダは `strict` のときだけ規則を述べる:「day starts 05:00 ·
  sessions cut at the boundary」。既定の規則では何も言わない——既定に説明は要らない。
- ポップオーバー: carried-in のセッションは "started 05:00" ではなく
  "since the day began, 05:00" と読ませ、それ以前の時間がどこへ行ったかを 1 文で
  添える。起きたときだけ表示する。

**チャートは変更しない。** `strict` では列はちょうど 24h に達しうるが超えない。
ADR 0001 の y ドメイン（それ以上を許す必要があった）が既に覆っている。描画側が
モードを知る必要は無い。

## 3. 帰結

- 単一のペイロード形状から両方の規則を描ける。UI にモード切替は無く、経路も 1 本。
- 切断が黙って起きることはない。境界時刻を出す面は、それが境界であることも出す。
- `config.toml` の `work.day_boundary` が GUI に効くのは、対応した CLI を同梱した
  版からである——同梱コピーが信頼の起点であり、それはリリース時に更新される。

## 4. テスト計画

- `strict` の timeline ペイロードが日とセッションの両方でフラグ付きで復号でき、
  `Format.carryNote` が 3 ケースをそれぞれ描く。
- carried フィールドの無いペイロード（既定の規則、または古い CLI）が全フラグ false・
  ノート無しで復号できる。
- `day_start_hour` / `day_boundary` の無い `status` が復号でき、
  `cutsSessionsAtDayBoundary == false`、日開始ラベルは nil。
- `carried_in` の now セッションが復号でき、境界リセットで生じた小さな
  `active_seconds` を保つ。
